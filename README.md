# MergeIt — Record Merger for Dataverse (Power Platform ToolBox)

MergeIt for [Power Platform ToolBox](https://www.powerplatformtoolbox.com/) is a web version of the MergeIt XrmToolBox plugin. It merges two **active** records from the same Dynamics 365 / Dataverse table:

- The **Master** is kept and receives the values you pick from the Slave, field by field.
- The **Slave** is deactivated after the merge.

Two merge modes are available:

| Mode | What it does |
|---|---|
| **Manual (transaction)**, all tables | A single Web API `$batch` changeset updates the Master (changed fields only) and deactivates the Slave (`statecode = 1`, and `statuscode` set to the metadata `DefaultStatus`). You can also reassign the Slave's child records (1:N relationships) in the same changeset. Either every operation succeeds or none is applied. |
| **Native merge (`Merge` action)**, account, contact, lead and incident only | Dataverse updates the Master with `UpdateContent` (built from your choices), reassigns **all** of the Slave's child records, and deactivates the Slave by linking it to the Master. |

## Project structure

The project follows the React + Vite template generated by `yo pptb` ([tool development docs](https://docs.powerplatformtoolbox.com/tool-development)).

```
MergeIt-PPTB/
├── package.json               Tool manifest: displayName, icon, features, configurations…
├── index.html                 Vite entry point (main = index.html in dist)
├── vite.config.ts             IIFE bundle + HTML fix-up for the ToolBox iframe
├── public/
│   └── icon/mergeit.svg       Tool icon: the MergeIt logo embedded in an SVG (copied to dist/icon)
└── src/
    ├── main.tsx               React bootstrap
    ├── App.tsx                UI orchestration: tables, records, Master/Slave, comparison, merge
    ├── index.css              MergeIt theme (Master blue / Slave orange), follows the ToolBox light/dark theme
    ├── assets/logo.png        Logo shown in the header
    ├── components/            Header, RecordsCard (1), CompareCard (2), MergeCard (3), Dialogs, Common
    ├── hooks/useToolbox.ts    Settings (toolboxAPI.settings), theme, connection, events
    ├── i18n/                  All UI text, in English and French
    ├── models/types.ts        Records, metadata, comparison rows, merge plan, settings
    ├── helpers/               Mergeable-attribute rules and value formatting/comparison
    └── services/              dataverse.ts (Web API helpers), metadataService, recordService, mergeService
```

The list of excluded system attributes is in `src/helpers/attributeFilter.ts` (`SystemExcludedAttributes`). You can add more exclusions in **Options** without rebuilding.

### Mapping from the XrmToolBox plugin

| XrmToolBox (C# / SDK) | Power Platform ToolBox (TypeScript / Web API) |
|---|---|
| `RetrieveAllEntitiesRequest`, `RetrieveEntityRequest` | `dataverseAPI.getAllEntitiesMetadata`, `getEntityMetadata`, `EntityDefinitions` queries |
| `RetrieveMultiple` with FetchXML and a paging cookie | `dataverseAPI.fetchXmlQuery` with `page` and `paging-cookie` |
| `ExecuteTransactionRequest` | `dataverseAPI.executeTransaction` (`$batch` changeset, 1,000 operations max) |
| `ExecuteMultipleRequest` (child counts) | `dataverseAPI.executeBatch` |
| `MergeRequest` | `dataverseAPI.execute({ operationName: 'Merge', operationType: 'action' })` |
| `WhoAmI`, `RetrieveUserPrivileges`, `RetrieveTeamPrivileges` | `dataverseAPI.execute` (functions) |
| `SettingsManager` | `toolboxAPI.settings` |
| `MessageBox`, `WorkAsync` | Fluent UI dialogs, busy overlay, `toolboxAPI.utils.showNotification` |

Lookups are written with `navigation-property@odata.bind`. The navigation property comes from the table's N:1 relationship metadata, so polymorphic lookups such as customer and owner work too.

## Build

Requirements: Node.js 18 or later.

```bash
npm install
npm run build        # type-check + vite build -> dist/
npm run dev-watch    # development build with source maps, rebuilt on save
npm run validate     # pptb-validate: checks package.json against the ToolBox rules
```

## Automated tests

```bash
npm run test:e2e
```

The end-to-end suite (`tests/e2e/run.cjs`) builds the tool, serves it, and drives Microsoft Edge or Chrome in headless mode. It runs against an in-memory Dataverse (`tests/e2e/mockDataverse.js`) that behaves like the ToolBox host and the Web API:
- FetchXML runs against the real entity set name, and attribute names and value types are validated.
- Responses carry formatted values and lookup annotations.
- Transactions are all-or-nothing, and `@odata.bind` payloads are checked.
- Any extra request header fails the test, because the ToolBox would show a consent prompt for it.

The suite covers table loading and filtering, views, search, Master/Slave selection, the comparison, manual and native merges (with the resulting data checked), rollback, options, settings persistence, language, and theme. Screenshots of failing tests go to `tests/e2e/screenshots/`. Set `PW_BROWSER` if your browser isn't in a standard location.

## Test in Power Platform ToolBox

1. Run `npm run build`.
2. In Power Platform ToolBox, open **Settings**, turn on **Show Debug Menu**, and select **Save**.
3. In the **Debug** section, under **Load Local Tool**, select **Browse**, pick this folder (the one that contains `package.json`), then select **Load Tool**.
4. Open **MergeIt** and pick a connection. The tool declares one required Dataverse connection (`features.connections = 1`).
5. After you rebuild, close the tool tab and open it again.

### Suggested test scenario (development or sandbox environment)

1. Create two test accounts, for example "Test Merge A" (Master) and "Test Merge B" (Slave). Fill in different fields, and leave one field empty on A but filled on B. Link a contact and a task to B.
2. Pick the **Account (account)** table, type `Test Merge`, then press Enter.
3. Select A and choose **Set as Master**. Select B and choose **Set as Slave**.
4. Select **Compare**, then check that:
   - Rows with different values are highlighted and identical rows are greyed out.
   - The field that is empty on A is preselected from the Slave.
5. In **Manual** mode, select **Reassign the Slave's child records**. Review the relationships and their record counts, select **Merge records**, and review the summary.
6. In Dataverse, check that A has the selected values, B is inactive, and the contact and task now point to A.
7. Repeat with **Native merge** on two other accounts.

## Features at a glance

- **Language**: English by default. Switch to French from the 🌐 menu in the header. The change applies right away and is saved.
- **Tables**: a searchable "Display name (logical_name)" list. Only tables that support Advanced Find, are customizable, have `statecode`, and aren't intersect or virtual tables are listed. By default, only tables you can read and write are shown. The last table you picked is remembered.
- **Loading**:
  - *(default load)* + **Load**: active records, paged, up to the limit set in Options (5,000 by default).
  - **Search**: typing filters the loaded rows instantly. Press Enter or select **Search** to run a server-side `like '%text%'` search on the primary name and the selected **search fields** (remembered per table).
  - **View**: system and personal views. Their FetchXML runs with paging and is restricted to active records. Columns follow the view's `layoutxml`.
- **Selection**: use the buttons or right-click a row, then **Swap** if needed. A record can't be both Master and Slave.
- **Comparison**: click a value (or its dot) to choose its source. Keyboard: `M` for Master, `S` for Slave, `Space` to toggle. Other options: **All from Master** / **All from Slave** (for the displayed rows), *Only differences*, *Hide empty on both sides*, a field filter, and *Include owner (ownerid)*.
- **Options**: record limit, Read + Write table filter, "Slave if Master is empty" rule, `transactioncurrencyid`, and extra exclusions.

## Known limitations

- **Slave deactivation (manual mode)**: the tool sets `statecode = 1` with the default status. Some tables need a dedicated message to reach state 1 because it isn't simply "Inactive": case (Resolved), lead (Qualified), opportunity (Won), quote, order, and others. Dataverse requires `CloseIncident`, `QualifyLead`, `WinOpportunity`, and so on, so the transaction fails and nothing changes. Use **Native merge** for cases and leads.
- **Unsupported fields**: images, files and multi-select choices (Virtual type), PartyList (`to`, `from`, and so on), calculated and rollup columns, derived attributes, and `*_base` fields.
- **Money values**: copied as-is. If the Master and Slave use different currencies, the amount is read in the Master's currency.
- **Child reassignment (manual mode)**:
  - Only 1:N relationships on the primary key are handled. N:N relationships aren't reassigned.
  - Some system tables are excluded (`activitypointer`, `activityparty`, `customeraddress`, `principalobjectaccess`, `asyncoperation`, and others). See `ExcludedChildEntities` in `src/services/mergeService.ts`.
  - Dataverse may reject updates to **inactive** child records, such as completed activities, and then the whole transaction fails. Clear that relationship or use Native merge.
  - Above **1,000 operations** (the changeset limit), reassignments are split across several transactions. The last transaction always holds the Master update and the Slave deactivation. If a batch fails, the batches before it stay applied. The confirmation dialog warns you about this.
- **Native merge**: requires merge privileges. `PerformParentingChecks` is `false`. Dataverse reassigns every relationship and you can't filter them.
- **Search**: `like '%text%'` doesn't use indexes and can be slow on large tables. Any `%`, `_` or `[` you type acts as a wildcard.
- **Views**: aggregate views aren't supported. Columns from linked tables appear as `attribute (alias)`.
- **Server-side logic**: plugins, workflows, business rules and required-field checks run as usual. A merge that clears a required field fails.
- **No undo**: test in a development environment first. If auditing is on, Dataverse records the changes.
